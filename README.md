# 学习目标管理台 · 微信小程序（微信一键登录 + 多设备同步）

微信原生小程序 + 微信云开发。**没有账号密码，也没有登录表单**：
点一下「微信一键登录」，当前微信就是你的账号，打卡记录自动同步。

不引第三方 UI 库、不引位图资源、不引任何 CDN。

---

## 一、五分钟看懂设计

### 身份就是 openid

小程序天然带 `openid`，云函数每次被调用时由微信注入（`cloud.getWXContext()`），
**客户端拿不到、也伪造不了**。所以整套「注册 / 登录 / 找回密码 / 改密 / 会话令牌」
都可以删掉，只留一个动作：

```
第一次点「微信一键登录」 → 用当前 openid 建号
之后每次打开         → 同一个 openid 命中同一个账号
```

比原来的邮箱 + 密码方案更安全的点在于：**没有可泄露的凭据**。
原来客户端存了一个令牌，令牌可能被拿走；现在客户端什么都不用存，
每次请求的身份都由微信在服务端注入。

### 代价（必须知道）

账号跟着这个微信号走：

| 场景 | 结果 |
|---|---|
| 换手机，用同一个微信登录 | 数据还在 |
| 重装微信、换微信号 | 数据找不回来 |
| 微信被封 / 注销 | 数据找不回来 |

这条限制在登录页和「我的 → 关于你的数据」里都写明了，不是藏在文档里的免责声明。

如果哪天需要「换微信号也能带走数据」，加回来的最小方案是
**在 openid 之上挂一个可选的联系方式**（只用于人工找回，不参与登录），
而不是把密码登录整套搬回来。

### 数据怎么跟账号走

打卡数据不存进 `accounts`，而是按账号分片存放在 `sync_docs`：

| 分片 key | 内容 | 为什么这样切 |
|---|---|---|
| `core` | 目标、每周复盘、偏好设置 | 体积小、改动频繁，整片同步最简单 |
| `logs:2026-10` | 该月的打卡记录 | 记录是只增的长列表，按月切分后每次只搬动变化的一两个月 |

每个分片带一个**服务端自增的 `rev`**（不是时间戳 —— 设备时钟不可信）。
推送时带上 `baseRev`，服务端用原子条件更新做 CAS：

```
baseRev == 当前 rev  → 写入成功，rev + 1
baseRev != 当前 rev  → 拒绝，回传权威数据，客户端合并后重推
```

合并规则（`miniprogram/utils/model.js` 的 `merge*`，纯函数、可测）：

- **打卡记录** 按 `id` 取并集（记录本身不可变，天然无冲突）
- **目标 / 复盘 / 设置** 按 `updatedAt` 做 LWW，删除写成**墓碑**而不是物理删除
- 时间戳打平时一律取云端那份 → 两端用任意顺序合并都收敛到同一结果
  （这一点有专门的测试：`tests/model.test.mjs` 的「并发分叉」用例）

### 未登录时怎么办

**不封锁功能，界面上也不解释。** 新用户打开就能建目标、打卡（写本机）。
今日页头部只有一个「登录」小字入口 —— 不弹说明、不写「数据只在这台手机上」。

> **产品原则（2026-10-22）**：界面只放功能。隐私说明、数据流向、身份模型
> 属于本文档，不属于界面。把「我们为什么收集数据」印在界面上，反而会制造
> 「这产品有事瞒着我」的异样感。

一旦登录，`store.onLoggedIn()` 会先**全量拉**（把账号里已有的数据并进来）
再**全量推**（把游客期间的数据带上去）—— 两边的数据都会保留，不会出现
「登录后我的记录没了」。

例外：冷启动如果命中足够新鲜的预拉取快照（见 §六点六），那次全量拉会被跳过
（`onLoggedIn({ skipPull: true })`），只推真正脏的分片 —— 快照本身就是云端最新。

## 三、部署（照做即可）

### 步骤 1 · 准备 AppID

个人主体即可（纯工具、无支付、无 UGC）。AppID 已填进 `project.config.json`。

### 步骤 2 · 创建云开发环境

开发者工具 → 工具栏「云开发」→ 新建环境。拿到**环境 ID**，填进
`miniprogram/utils/config.js`：

```js
const ENV_ID = '你的环境ID';
```

> 留空时小程序进入「本地模式」：登录不可用并给出明确的配置提示，
> 打卡仍可离线记录。

### 步骤 3 · 建集合与索引（比旧版少很多）

在云开发控制台 → 数据库里创建 **2 个集合**：

| 集合 | 用途 |
|---|---|
| `accounts` | 微信账号（openid、昵称、状态、加入时间） |
| `sync_docs` | 打卡数据分片 |

索引只需要 **2 个**，而且都必须是「唯一」：

| 集合 | 字段 | 唯一 | 说明 |
|---|---|---|---|
| `accounts` | `openid` | **是** | 一个微信一个账号的最后一道防线 |
| `sync_docs` | `userId` + `key` | **是** | 一个账号一个分片一条文档 |

> 旧版需要的 `sessions` / `verify_codes` / `rate_limits` 三个集合**不再需要**，
> 已建过的话可以直接删掉（没有代码再读写它们）。

### 步骤 4 · 设置集合权限（重要）

每个集合 → 权限设置 → 选 **「所有用户不可读写」**。

所有数据访问都经过云函数（云函数默认有管理员权限）。客户端不直连数据库，
必须这样设，否则任何人都能在小程序里直接读写你的数据库。

### 步骤 5 · 上传部署三个云函数

在开发者工具的 `cloudfunctions` 目录下，对 `auth`、`sync`、`prefetch` 分别：
**右键 → 上传并部署：云端安装依赖**。

### 步骤 5.5 · 开启数据预拉取（可选，冷启动更快）

个人主体只能选云开发环境，正好不用另买服务器：

1. 小程序后台 **开发 → 开发管理 → 开发设置 → 数据预拉取 → 开启**；
2. 数据来源选 **云开发**，环境选 `demo-d4ggmg7lf4736fb7c`，
   云函数选 **prefetch**（就是上一步部署的那个）；
3. 真机冷启动一次，看云开发控制台 → 云函数 → `prefetch` → 日志：
   出现 `event keys=...` 与 `ok via=...` 就说明链路通了；
   日志里的 `via=event` 表示身份来自微信预拉取请求（正常），
   `via=context` 表示是客户端直接调用（测试用）。

没有配置也不影响功能：客户端读不到缓存时会安静地走常规 `sync.pull`，
只是少了一次「代码包加载前就把数据准备好」的加速。
配置之后冷启动若命中新鲜快照（10 分钟内、未裁剪、账号一致），
登录对齐会跳过那次全量拉取，只推本机真正脏的分片。

### 步骤 6 · 环境变量

**一个都不需要。** 没有邮件/短信通道、没有密码加盐、没有会话策略。
旧版配过的 `AUTH_*` 变量可以全部清掉，代码不再读取。

### 步骤 7 · 联调自测清单

1. 打开小程序 → 今日页应显示「数据只在这台手机上」的引导条；
2. 新建一个目标 → 能创建、能打卡（此时不会发任何云函数请求）；
3. 点引导条 → 登录页 → 点「微信一键登录」→ 应提示「账号已创建」并跳回今日页；
4. 打卡几次 → 「我的 → 数据与同步 → 立即同步」→ 提示「已同步」；
5. 清掉开发者工具的缓存（模拟换手机）→ 再点一次微信一键登录 →
   **应该看到刚才的全部目标与打卡记录**（同一个开发者工具 = 同一个测试微信号）；
6. 「我的 → 退出登录」→ 回到未登录，但本机记录一条不少；
7. 「我的 → 清空云端数据」→ 输入 DELETE → 云端分片归零；
8. 真机用另一个微信打开 → 应是一个全新的空账号（不同 openid 互不可见）。

## 四、安全设计（逐条对应实现位置）

| 关注点 | 做法 | 位置 |
|---|---|---|
| 身份来源 | openid 由 `cloud.getWXContext()` 注入，**不接受请求体里的任何身份字段** | `*/index.js`、`*/lib/service.js` |
| 客户端凭据 | 一个都不存。本地只缓存 `{ user }` 用于渲染，删掉也不影响下次进入 | `utils/auth.js` |
| 越权 | `sync` 的每个动作先 `requireAccount(ctx)`，`userId` 一律来自 openid 查出的账号 | `sync/lib/service.js` |
| 账号伪造 | 没有密码就没有「撞库」；没有令牌就没有「令牌泄露」 | —— |
| 重复建号 | `accounts.openid` 唯一索引兜底；并发首次登录时撞索引会回查已有账号 | `auth/lib/service.js` 的 `login` |
| 对外泄露 | `publicUser()` 只返回 `id / nickname / createdAt`，不透出 openid、unionid、`_openid` | 同上 |
| 停用账号 | `status !== 'active'` 时登录与同步都拒绝 | 同上、`sync/lib/service.js` |
| 载荷注入 | 服务端对客户端分片做白名单取字段 + 上限截断 + 字节数限制 | `sync/lib/shard.js` |
| 危险操作 | 清空云端数据要求显式 `confirm: 'DELETE'`（前端还会做二次输入确认） | `sync/lib/service.js` |
| 数据库权限 | 集合权限设为「所有用户不可读写」，客户端只能走云函数 | 见「部署步骤 4」 |
| 错误封装 | 云函数永不把异常直接抛给客户端，统一 `{ ok, code, message }` | `*/lib/errors.js` |

### 已知取舍（说清楚，不藏着）

1. **数据跟着微信号走。** 换手机没事，换微信号就找不回来。这是「不要密码」的直接代价。
2. **目标是软删除**（打墓碑），所以数据量只增不减。墓碑在 90 天后由客户端合并时清理。
3. `state.snapshots`（当天建议量的快照）**不进云端** —— 它由每台设备各自的
   目标与记录推导，同步过去只会制造无意义的写冲突。
4. **不再有设备列表。** 没有会话就没有「哪几台设备在线」这个概念；
   `sync_docs` 里仍记录最后写入的 `deviceId`，只用于排查问题。

## 六点六、数据预拉取（2026-10-26）

冷启动时，微信会**先于代码包加载**调用一次后台配置的云函数，把返回的字符串缓存到本机；
代码跑起来后用 `wx.getBackgroundFetchData({ fetchType: 'pre' })` 取回。这样首屏可以
直接用云端快照，而不必等「会话恢复 → 全量拉取」这条网络链路。

### 为什么走云开发而不是 HTTPS

官方规定：**个人主体只能配置云开发环境**（非个人主体才能填 HTTPS 地址）。
这个项目正好是个人主体 + 云开发，后台直接选 `prefetch` 云函数即可。

### 三条协议约束（实现必须遵守）

1. **返回值必须是字符串**，整个 body 会被原样缓存；且不超过 256KB。
   本项目自己卡在 200KB：core 一定保留，月份从新到旧装，装不下就丢最旧的并标
   `partial: true`。
2. **这个调用不是客户端发起的**，`cloud.getWXContext().OPENID` 可能为空，
   微信把身份放在 `event.openId` / `event.userInfo.openId` 里。
   但 event 客户端可以伪造（任何人能直接 `wx.cloud.callFunction` 调它），
   所以规则是：**ctx.openid 存在时只认 ctx；只有 ctx 为空才退到 event**。
   客户端直接调用时 ctx 一定存在，伪造的 openId 会被忽略。
3. **冷启动关键路径**：只做两次只读查询（accounts → sync_docs），不写库、不合并、
   不调其它云函数。出错返回空载荷字符串，让客户端安静降级到常规 `sync.pull`。

### 客户端采纳闸门（store.applyPrefetched）

- 快照的 `userId` 必须等于本机缓存的账号 → 换微信号后不会串数据；
- 本机分片 `dirty`（有未推送改动）时跳过该分片 → 离线改动不会被快照抹掉；
- 只接受 `rev` 更大的分片，与普通 pull 的判定完全一致；
- 采纳后不标 dirty：数据本来就是云端的，不需要推回去。

`app.boot()` 的顺序是「读缓存 → 采纳 → 恢复会话」。若快照足够新鲜
（10 分钟内、未裁剪、账号一致），`store.onLoggedIn({ skipPull: true })`
会跳过登录后的全量拉取，只推真正脏的分片；别的设备若有新改动，
由 push 的 CAS 回传权威数据、客户端合并后重推 —— 与平时的冲突收敛是同一条路径。

### 怎么验证

- **开发者工具不会触发预拉取**（它是微信客户端的行为）。真机冷启动，
  然后看云开发控制台 → 云函数 → `prefetch` → 日志：
  `event keys=...` + `ok via=event ...` 表示命中；`via=context` 是客户端直接调用。
- 客户端没有可观测日志（预拉取失败必须安静）。要确认是否采纳，
  可在冷启动后看「我的 → 数据与同步」是否立即有云端统计，或临时打点。
- 后台数据预拉取没开 / 云函数没部署时，一切照旧 —— 只是退回普通拉取。

## 六点九、用户隐私合规（对照官方《小程序用户隐私保护指引》核对，2026-10-25）

**结论：本项目零隐私授权接口使用。** 全量扫描 wx API：仅 UI / 存储 / 音频 / 导航 /
主题类接口；无 getUserProfile、chooseAvatar、type="nickname" 输入、位置、相册、
摄像头、麦克风、剪贴板（读与写都没有）、蓝牙、运动步数、传感器。后台不会生成
强制必填隐私项，也不会触发隐私弹窗要求。

如实申报范围（填后台指引时照抄）：

| 信息 | 用途 | 存储 | 对应声明 |
|---|---|---|---|
| 微信 openid | 创建账号、归属打卡数据 | 云开发环境，随账号存续 | 官方清单无此项，无需弹窗；在自定义说明中如实写明 |
| 用户主动填写的资料（昵称 / 目标 / 复盘文本） | 功能实现与多设备同步 | 同上 | 「用户主动提供的信息」，非微信资料拉取 |
| 打卡行为记录（何时/哪项/数量） | 用户自己的统计与进度 | 同上 | 官方清单无此项 |

- 不向第三方提供数据（仅存开发者自己的微信云开发环境）。
- 存储期限：账号存续期间；**注销账号即删除**（auth.deleteAccount 连同云端分片，
  代码已实现并有测试）。
- 若未来引入头像/昵称拉取、位置、剪贴板读取等，必须先在后台更新指引并接
  wx.requirePrivacyAuthorize，再发版。

**提审表单的「测试账号 / 密码」填法**：本小程序是微信一键登录（openid 机制），

- 账号：`本小程序使用微信一键登录，无需账号`
